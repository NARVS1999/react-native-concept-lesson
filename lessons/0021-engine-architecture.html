Lesson 0021: Engine and Architecture

Phase 7 — Advanced Concepts

Lesson Goal Understand the Hermes JavaScript engine and React Native's New Architecture (Fabric + Turbo Modules).

Hermes Engine

Hermes is a JavaScript engine built by Meta specifically for React Native. It's the default JS engine since RN 0.70.

FeatureJavaScriptCore (JSC)Hermes
Startup timeSlowerFaster (bytecode precompilation)
Memory usageHigherLower (optimized GC)
App sizeLargerSmaller (bytecode is more compact)
DebuggingChrome debuggerChrome debugger + Hermes debugger
Key Insight Hermes pre-compiles JavaScript to bytecode during the build step. This means the app doesn't need to compile JS at runtime — dramatically improving cold start time.

New Architecture

React Native's New Architecture replaces the old Bridge with three key components:

Fabric (New Renderer)

Fabric replaces the old rendering pipeline. It enables:

  • Synchronous rendering — UI updates happen immediately, not asynchronously
  • Concurrent features — React can interrupt and resume rendering
  • Better TypeScript support — Native components are typed via codegen

Turbo Modules (New Native System)

Turbo Modules replace old Native Modules with:

  • Lazy loading — modules load on demand, not at startup
  • Synchronous calls via JSI — no JSON serialization
  • Type safety via codegen specs

Codegen

Codegen automatically generates native code from TypeScript/Flow specs — eliminating manual bridging code.

Migration Path

Apps can adopt the New Architecture incrementally:

1

Ensure all dependencies support the New Architecture

2

Enable the New Architecture flag in your project

3

Migrate native modules to Turbo Modules one at a time

4

Migrate custom native components to Fabric components

Summary

  • Hermes pre-compiles JS to bytecode for faster startup and smaller bundles
  • Fabric is the new renderer enabling synchronous, concurrent updates
  • Turbo Modules replace Native Modules with lazy loading and JSI
  • Codegen generates native code from TypeScript specs
