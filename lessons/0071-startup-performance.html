Lesson 71: Startup Performance

Phase 9 — Optimization Concepts

Lesson Goal Understand Hermes bytecode compilation, implement lazy screen loading, optimize splash screens, use inline requires, and measure your app's cold start time.

Why Startup Time Matters

Cold start time is the time from when a user taps your app icon to when the first screen appears. Users expect apps to load in under 2 seconds. Every additional second of startup time increases abandonment rates by up to 30%.

Hermes Bytecode Compilation

Hermes is React Native's default JavaScript engine. It pre-compiles JavaScript to bytecode at build time, which means the app doesn't need to parse raw JS at startup — it loads pre-compiled bytecode directly.

// Hermes is enabled by default in new React Native projects
// Check android/app/build.gradle:
project.ext.react = [
    enableHermes: true,  // <-- ensure this is true
]

// To verify Hermes is running in your app:
if (global.HermesInternal) {
  console.log('Using Hermes engine');
} else {
  console.log('Not using Hermes — consider enabling it');
}

// Hermes bytecode is generated during the build process
// android/app/build/intermediates/merged_js/ for Android
// ios/build/ for iOS

Lazy Loading Screens

Don't load all screens at startup. Load them only when the user navigates to them for the first time.

import React, { Suspense, lazy } from 'react';
import { ActivityIndicator, View } from 'react-native';
import { NavigationContainer } from '@react-navigation/native';
import { createNativeStackNavigator } from '@react-navigation/native-stack';

// Only HomeScreen is loaded immediately
const HomeScreen = lazy(() => import('./screens/HomeScreen'));

// These load on-demand when navigated to
const ProfileScreen = lazy(() => import('./screens/ProfileScreen'));
const SettingsScreen = lazy(() => import('./screens/SettingsScreen'));
const ChatScreen = lazy(() => import('./screens/ChatScreen'));

const Stack = createNativeStackNavigator();

function LoadingFallback() {
  return (
    <View style={{ flex: 1, justifyContent: 'center', alignItems: 'center' }}>
      <ActivityIndicator size="large" />
    </View>
  );
}

export default function App() {
  return (
    <NavigationContainer>
      <Suspense fallback={<LoadingFallback />}>
        <Stack.Navigator initialRouteName="Home">
          <Stack.Screen name="Home" component={HomeScreen} />
          <Stack.Screen name="Profile" component={ProfileScreen} />
          <Stack.Screen name="Settings" component={SettingsScreen} />
          <Stack.Screen name="Chat" component={ChatScreen} />
        </Stack.Navigator>
      </Suspense>
    </NavigationContainer>
  );
}

Splash Screen Optimization

The splash screen is the first thing users see. It should display instantly and while your app loads. Use react-native-splash-screen to keep it visible until your app is ready.

// Install: npm install react-native-splash-screen

// In your root component (App.js)
import React, { useEffect } from 'react';
import SplashScreen from 'react-native-splash-screen';

export default function App() {
  useEffect(() => {
    // Hide splash after your app is fully loaded
    // e.g., after fetching initial data
    initializeApp().then(() => {
      SplashScreen.hide();
    });
  }, []);

  return (
    // Your app content
  );
}

Inline Requires

Inline requires defer the loading of a module until it's actually used. Instead of importing everything at the top of your file, require modules where they're first used.

// BEFORE: All imports loaded at startup
import React from 'react';
import { View, Text, StyleSheet } from 'react-native';
import HeavyComponent from './HeavyComponent';
import Analytics from './Analytics';

function HomeScreen() {
  const handlePress = () => {
    Analytics.track('button_pressed');
  };

  return (
    <View>
      <HeavyComponent />
      <Button onPress={handlePress} title="Press" />
    </View>
  );
}

// AFTER: Inline requires — modules load only when first used
import React from 'react';
import { View, Text, StyleSheet, Button } from 'react-native';

function HomeScreen() {
  const handlePress = () => {
    // Analytics module loads only when button is pressed
    const Analytics = require('./Analytics');
    Analytics.track('button_pressed');
  };

  const renderHeavy = () => {
    // HeavyComponent loads only when this function is called
    const HeavyComponent = require('./HeavyComponent');
    return <HeavyComponent />;
  };

  return (
    <View>
      {renderHeavy()}
      <Button onPress={handlePress} title="Press" />
    </View>
  );
}

// For React Navigation screens, use lazy() which is an inline require
const ChatScreen = lazy(() => require('./screens/ChatScreen'));

Measuring Cold Start Time

Use Xcode Instruments (iOS) or Android Studio Profiler to measure cold start time precisely. You can also measure it programmatically.

// Measure time from app start to first render
import { PerformanceObserver } from 'react-native-performance';

// Log startup time
const startTime = Date.now();

// In your root component's useEffect
useEffect(() => {
  const startupTime = Date.now() - startTime;
  console.log(`Cold start time: ${startupTime}ms`);

  // Send to analytics
  Analytics.track('startup_time', { duration: startupTime });
}, []);

Summary

  • Hermes pre-compiles JavaScript to bytecode at build time, eliminating parsing overhead at startup
  • Lazy loading screens with React.lazy() defers non-critical screen code to reduce initial load
  • Splash screens should stay visible until the app is fully initialized, then hide programmatically
  • Inline requires defer module loading until the code path is actually executed
  • Measure cold start time with Xcode Instruments, Android Profiler, or programmatic timing
  • Target under 2 seconds for cold start — every additional second increases abandonment rates
  • Profile first to identify bottlenecks, then apply targeted optimizations
