Lesson 1: React Native

Phase 1 — Foundational Concepts

Lesson Goal By the end of this lesson, you will understand what React Native is, how it renders native components, the differences between Expo and CLI, the JS-native bridge architecture, and why React Native is a compelling choice for cross-platform mobile development.

What is React Native?

React Native is an open-source framework created by Meta (Facebook) that allows developers to build mobile applications using JavaScript and React. Unlike React, which targets the web browser, React Native renders to real native platform components — meaning your app looks and feels like a truly native application on both iOS and Android.

When you write a <View> in React Native, it compiles to a real UIView on iOS and a real android.view.View on Android. This is fundamentally different from hybrid frameworks that simply wrap web content inside a WebView.

React Native was first released in 2015 and has since grown into one of the most popular mobile development frameworks. It powers apps like Instagram, Facebook, Shopify, Discord, Bloomberg, and many more.

How React Native Renders Native Components

React Native uses a bridge architecture to communicate between JavaScript and native code. Here is the rendering pipeline:

  1. JavaScript Thread: Your React components and business logic run on a dedicated JavaScript thread.
  2. Bridge: When the JS thread needs to update the UI, it serializes messages and sends them across an asynchronous bridge to the native side.
  3. Native Thread: The native platform receives these messages and updates the real native UI components accordingly.

In the newer architecture (known as the "New Architecture" or Fabric), React Native uses JavaScript Interface (JSI) instead of the older asynchronous bridge. JSI allows direct synchronous access to native objects from JavaScript, which significantly improves performance.

// React Native code that renders a native button
import React from 'react';
import { View, Text, Button, StyleSheet } from 'react-native';

export default function App() {
  return (
    <View style={styles.container}>
      <Text style={styles.title}>Hello React Native!</Text>
      <Button
        title="Press Me"
        onPress={() => alert('Button pressed!')}
      />
    </View>
  );
}

const styles = StyleSheet.create({
  container: {
    flex: 1,
    justifyContent: 'center',
    alignItems: 'center',
    backgroundColor: '#f5f5f5',
  },
  title: {
    fontSize: 24,
    fontWeight: 'bold',
    marginBottom: 20,
  },
});

In this example, View renders to a native view container, Text renders to native text, and Button renders to a platform-native button. None of these are HTML elements.

Expo vs CLI: A Detailed Comparison

When starting a React Native project, you have two primary options: Expo and React Native CLI (now often called bare workflow). Understanding the differences is crucial for choosing the right approach.

Feature Expo React Native CLI
Setup Time Seconds (npx create-expo-app) Minutes to hours (manual config)
Native Code Access Limited (use config plugins or eject) Full access to iOS and Android
Build System EAS Build (cloud-based) Local build with Xcode/Android Studio
OTA Updates Built-in via EAS Update Requires CodePush or custom solution
Learning Curve Beginner-friendly Requires native platform knowledge
Libraries Managed ecosystem (curated) Full npm ecosystem
Development Speed Fastest for most apps Faster for highly customized apps

The JS-Native Bridge Architecture

The traditional React Native architecture consists of three main threads:

  • JavaScript Thread: Runs your React code, state management, and business logic. This is where your components live.
  • Main/UI Thread: Handles user interactions and renders native views. This is the thread that manages the actual screen pixels.
  • Shadow Thread (Layout): Computes layout using Yoga (a cross-platform layout engine) before passing the final positions to the native thread.

Communication happens through a serialized JSON bridge. While this is asynchronous by default (which keeps the JS thread responsive), it can introduce latency for high-frequency events like scrolling or animations.

The new architecture introduces JSI (JavaScript Interface), which replaces the bridge with a synchronous, direct connection between JS and native code. This eliminates serialization overhead and enables features like shared C++ objects.

Why Use React Native Over Native Development?

There are several compelling reasons to choose React Native:

  • Code Sharing: Write once, run on both iOS and Android. This can save 40-60% of development time compared to building two separate native apps.
  • Single Codebase: Bug fixes and feature additions apply to both platforms simultaneously.
  • Fast Iteration: Features like Fast Refresh allow you to see changes instantly without rebuilding the entire app.
  • Large Ecosystem: Access to thousands of npm packages and a massive developer community.
  • Web Developer Friendly: If you know React for the web, you already know 80% of React Native.
  • Over-the-Air Updates: Push updates to users without going through the App Store or Play Store review process.

Cross-Platform Benefits

React Native's cross-platform nature extends beyond just sharing code:

  • Shared Business Logic: API calls, data processing, state management, and navigation all work identically on both platforms.
  • Shared UI Components: Most components render the same way on both platforms. Platform-specific differences are handled with Platform API or platform-specific files.
  • Consistent Design: Your app maintains a consistent look and feel across platforms while respecting platform conventions when needed.
  • Reduced Cost: One development team, one codebase, one deployment pipeline = significantly lower development and maintenance costs.

Mini-Project: Create and Run a Basic Expo App

Follow these steps to set up your first React Native project using Expo:

  1. Install Node.js (version 18 or later) from nodejs.org
  2. Run the following commands in your terminal:
# Install Expo CLI globally
npm install -g expo-cli

# Create a new Expo project
npx create-expo-app MyFirstApp

# Navigate into the project
cd MyFirstApp

# Start the development server
npx expo start

Then, modify App.js with the following content:

import React, { useState } from 'react';
import { View, Text, TextInput, Button, StyleSheet } from 'react-native';

export default function App() {
  const [name, setName] = useState('');
  const [greeting, setGreeting] = useState('');

  return (
    <View style={styles.container}>
      <Text style={styles.title}>Welcome to React Native!</Text>
      <TextInput
        style={styles.input}
        placeholder="Enter your name"
        value={name}
        onChangeText={setName}
      />
      <Button
        title="Say Hello"
        onPress={() => setGreeting(`Hello, ${name}!`)}
      />
      {greeting ? <Text style={styles.greeting}>{greeting}</Text> : null}
    </View>
  );
}

const styles = StyleSheet.create({
  container: {
    flex: 1,
    justifyContent: 'center',
    alignItems: 'center',
    padding: 20,
  },
  title: {
    fontSize: 24,
    fontWeight: 'bold',
    marginBottom: 20,
  },
  input: {
    borderWidth: 1,
    borderColor: '#ccc',
    borderRadius: 8,
    padding: 12,
    width: '100%',
    marginBottom: 15,
    fontSize: 16,
  },
  greeting: {
    marginTop: 20,
    fontSize: 20,
    color: '#3b82f6',
  },
});

Open the Expo Go app on your phone and scan the QR code, or press i for iOS simulator / a for Android emulator.

Summary

  • React Native renders to real native components, not WebViews
  • The JS-Native bridge architecture separates JS logic from native UI rendering
  • Expo is recommended for beginners due to faster setup and simpler workflow
  • React Native CLI gives full access to native code for advanced customization
  • Cross-platform development with RN can save significant time and resources
  • The new architecture (JSI) improves performance by eliminating the async bridge
  • React Native powers many production apps used by millions of people daily
