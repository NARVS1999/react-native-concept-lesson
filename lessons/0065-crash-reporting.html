Lesson 65: Crash Reporting and Error Tracking

Phase 8 — Production Concepts

Lesson Goal Set up crash reporting and error tracking in your React Native app using tools like Sentry, Crashlytics, and Bugsnag to monitor and fix issues in production.

Why Crash Reporting Matters

In development, you see every error immediately. In production, errors happen silently on thousands of devices you can't access. Crash reporting tools capture these errors and send them to a dashboard where you can analyze, prioritize, and fix them.

Setting Up Sentry

Sentry is the most popular choice for React Native crash reporting due to its excellent React Native SDK and source map support.

Installation

# Install Sentry SDK
npx @sentry/wizard@latest -i reactNative

# Or install manually
npm install @sentry/react-native

# For Expo projects
npx expo install @sentry/react-native

Initialization

// App.js or App.tsx
import * as Sentry from '@sentry/react-native';

Sentry.init({
  dsn: 'https://YOUR_DSN@sentry.io/YOUR_PROJECT_ID',
  tracesSampleRate: 1.0,
  environment: __DEV__ ? 'development' : 'production',
});

export default function App() {
  return (
    // Your app content
  );
}

// Wrap your app with Sentry
export default Sentry.wrap(App);

Capturing errors manually

import * as Sentry from '@sentry/react-native';

// Capture exceptions
try {
  // risky operation
} catch (error) {
  Sentry.captureException(error);
}

// Capture messages
Sentry.captureMessage('Something important happened', 'info');

// Add breadcrumbs for debugging context
Sentry.addBreadcrumb({
  category: 'navigation',
  message: 'Navigated to Profile screen',
  level: 'info',
});

// Set user context
Sentry.setUser({
  id: 'user-123',
  email: 'user@example.com',
});

Setting Up Crashlytics (Firebase)

# Install Firebase
npm install @react-native-firebase/app @react-native-firebase/crashlytics

# Initialize Firebase (follow React Native Firebase docs)
# Then use Crashlytics:

import crashlytics from '@react-native-firebase/crashlytics';

// Log non-fatal errors
crashlytics().log('User attempted to upload large file');

// Record errors
try {
  // operation
} catch (error) {
  crashlytics().recordError(error);
}

// Set custom attributes
crashlytics().setAttribute('user_type', 'premium');

// Force a crash (for testing only!)
// crashlytics().crash();

Setting Up Bugsnag

# Install Bugsnag
npm install @bugsnag/react-native

# Initialize in your app entry point
import Bugsnag from '@bugsnag/react-native';

Bugsnag.start({
  apiKey: 'YOUR_BUGSNAG_API_KEY',
  appVersion: '1.0.0',
  releaseStage: 'production',
});

// Capture errors
try {
  // operation
} catch (error) {
  Bugsnag.notify(error);
}

Source Maps for Readable Stack Traces

React Native minifies JavaScript code in production builds, making stack traces hard to read. Source maps translate minified code back to your original source code.

Generating source maps with EAS

# Source maps are generated automatically with EAS Build
# But you need to upload them to your crash reporting service

# For Sentry
npx @sentry/react-native expo-sourcemaps

# Or configure in app.json
{
  "expo": {
    "plugins": [
      [
        "@sentry/react-native/expo-plugin",
        {
          "organization": "your-org",
          "project": "your-project",
          "authToken": "your-auth-token"
        }
      ]
    ]
  }
}

Alerts and Notifications

Configure alerts to be notified of new issues:

  • Email alerts — Get notified when new issues appear
  • Slack integration — Post errors to your team's Slack channel
  • PagerDuty/OpsGenie — Page on-call engineers for critical errors
  • Issue alerts — Trigger when error count exceeds thresholds
// Example: Sentry alert rules (configured in Sentry dashboard)
// Alert when:
// - New issue is created
// - Error count > 100 in 1 hour
// - Affected users > 50 in 24 hours

Best Practices

  • Always upload source maps with production builds
  • Add meaningful context (user info, app version, device info) to error reports
  • Use breadcrumbs to track user actions leading up to errors
  • Set up alerts for critical errors that affect many users
  • Review and triage crash reports regularly as part of your sprint
  • Use error boundaries to catch and report React component errors

Mini-Project: Add Sentry to Your App

Integrate Sentry error tracking into your React Native project:

# Step 1: Install Sentry
npx @sentry/wizard@latest -i reactNative

# Step 2: Initialize Sentry in App.js
import * as Sentry from '@sentry/react-native';

Sentry.init({
  dsn: 'YOUR_DSN_HERE',
  tracesSampleRate: 1.0,
  environment: __DEV__ ? 'development' : 'production',
  enableAutoSessionTracking: true,
});

export default Sentry.wrap(App);

# Step 3: Add a test error button
<Button
  title="Throw Test Error"
  onPress={() => {
    try {
      throw new Error('Test crash from Sentry!');
    } catch (error) {
      Sentry.captureException(error);
    }
  }}
/>

# Step 4: Add breadcrumbs to track navigation
import { useEffect } from 'react';
import { useNavigation } from '@react-navigation/native';

function Screen() {
  const navigation = useNavigation();
  useEffect(() => {
    Sentry.addBreadcrumb({
      category: 'navigation',
      message: `Navigated to ${navigation.getState().routeName}`,
    });
  }, []);
  // ...
}

# Step 5: Build and test — verify errors appear in Sentry dashboard

Visit your Sentry dashboard to see the captured error with full context and stack trace.

Summary

  • Crash reporting tools capture production errors that you can't reproduce locally
  • Sentry, Crashlytics, and Bugsnag are popular choices with React Native support
  • Source maps translate minified production code into readable stack traces
  • Breadcrumbs track user actions leading up to errors for better debugging context
  • Configure alerts to notify your team of critical errors in real time
  • Always upload source maps with production builds for meaningful error reports
