What are Native Modules?

Native modules allow you to access platform-specific APIs that aren't available in React Native's JavaScript layer. They are written in Swift (iOS) or Kotlin (Android) and exposed to JavaScript through a bridge.

Why use native modules?

  • Access platform-specific features (Bluetooth, NFC, biometrics)
  • Performance-critical operations that can't be done in JS
  • Wrapping existing native SDKs and libraries
  • Platform-specific UI components not available in React Native

The Bridge Architecture (Legacy)

In React Native's old architecture, communication between JavaScript and native code happens through an asynchronous "bridge". JS sends messages, and native code processes them.

// JavaScript side
import { NativeModules } from 'react-native';
const { DeviceInfo } = NativeModules;

// Call native method
const deviceName = await DeviceInfo.getDeviceName();
console.log(deviceName);

How the Bridge Works

  1. JavaScript calls a native method through the bridge
  2. The call is serialized into JSON and sent to the native thread
  3. Native code processes the request
  4. Result is serialized and sent back through the bridge
  5. JavaScript receives the result asynchronously

This is inherently asynchronous — you can't get synchronous results from native code through the bridge.

Creating a Simple Native Module (Expo)

With Expo, you can create native modules using the Expo Modules API, which is simpler than the old bridge approach.

iOS (Swift)

// ios/MyModule.swift
import ExpoModulesCore

public class MyModule: Module {
  public func definition() -> ModuleDefinition {
    Name("MyModule")

    AsyncFunction("getDeviceName") { () -> String in
      return UIDevice.current.name
    }

    AsyncFunction("isRunningInSimulator") { () -> Bool in
      #if targetEnvironment(simulator)
        return true
      #else
        return false
      #endif
    }

    Function("getPlatform") { () -> String in
      return "iOS"
    }
  }
}

Android (Kotlin)

// android/src/main/java/xyz/myapp/mymodule/MyModule.kt
package xyz.myapp.mymodule

import expo.modules.kotlin.modules.Module
import expo.modules.kotlin.modules.ModuleDefinition
import android.os.Build

class MyModule : Module() {
  override fun definition() = ModuleDefinition {
    Name("MyModule")

    AsyncFunction("getDeviceName") {
      Build.MODEL
    }

    AsyncFunction("isRunningInSimulator") {
      Build.FINGERPRINT.contains("generic")
    }

    Function("getPlatform") {
      "Android"
    }
  }
}

Using in JavaScript

// JavaScript
import MyModule from './expo-module/my-module';

const deviceName = await MyModule.getDeviceName();
const isSim = await MyModule.isRunningInSimulator();
const platform = MyModule.getPlatform();

Understanding the Native Layer

When you write native modules, you need to understand the basics of iOS and Android development:

Swift Basics (iOS)

  • Swift is iOS's modern programming language
  • Classes and structs define data structures
  • Protocols define contracts for behavior
  • Error handling uses do/try/catch

Kotlin Basics (Android)

  • Kotlin is Android's preferred language (replaces Java)
  • Null safety prevents null pointer exceptions
  • Coroutines handle async operations
  • Extension functions add methods to existing classes

Summary

  • Native modules bridge JavaScript to platform-specific native code
  • The old bridge is asynchronous; Turbo Modules (new architecture) are synchronous via JSI
  • Expo Modules API simplifies creating native modules with Swift/Kotlin
  • Use native modules when no existing library covers your use case
  • iOS uses Swift; Android uses Kotlin for native modules
  • Always check for existing libraries before writing custom native code
