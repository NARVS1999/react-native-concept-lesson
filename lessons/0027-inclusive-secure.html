Lesson 0027: Inclusive and Secure Apps

Phase 10 — Expert/Strategic Concepts

Lesson Goal Build accessible apps with screen reader support, internationalize for global users, and harden security for sensitive data.

Accessibility (a11y)

Accessibility ensures your app works for everyone, including users with disabilities. React Native has built-in a11y support:

<Pressable
  accessible={true}
  accessibilityLabel="Add item to cart"
  accessibilityRole="button"
  accessibilityHint="Double tap to add item"
  onPress={addToCart}
>
  <Text>Add to Cart</Text>
</Pressable>
PropPurpose
accessibleMark element as accessible to screen readers
accessibilityLabelCustom label read by screen reader
accessibilityRoleRole: button, header, link, image, etc.
accessibilityHintDescribes what happens after action
accessibilityStateState: disabled, selected, checked
Key Insight Use accessibilityRole instead of relying on visual appearance alone. Screen readers don't see colors or shapes — they read semantics.

Internationalization (i18n)

Internationalization prepares your app for multiple languages. Use i18next with react-i18next:

import i18n from 'i18next';
import { initReactI18next } from 'react-i18next';

i18n.use(initReactI18next).init({
  resources: {
    en: { translation: { greeting: 'Hello', farewell: 'Goodbye' } },
    es: { translation: { greeting: 'Hola', farewell: 'Adios' } },
    tl: { translation: { greeting: 'Kamusta', farewell: 'Paalam' } },
  },
  lng: 'en',
  fallbackLng: 'en',
});

// In components
import { useTranslation } from 'react-i18next';

function Header() {
  const { t } = useTranslation();
  return <Text>{t('greeting')}</Text>;
}

Security Hardening

Protect sensitive data and user privacy:

ThreatSolution
Data in transitUse HTTPS everywhere, certificate pinning
Data at restUse encrypted storage (MMKV with encryption, Keychain)
API keys exposedNever hardcode keys — use environment variables
Code injectionValidate all user input, sanitize HTML
AuthenticationUse secure token storage, biometrics
// Secure storage for tokens
import * as SecureStore from 'expo-secure-store';

await SecureStore.setItemAsync('auth_token', token);
const token = await SecureStore.getItemAsync('auth_token');
await SecureStore.deleteItemAsync('auth_token');
Never
  • Commit API keys, secrets, or tokens to version control
  • Store sensitive data in AsyncStorage (it's unencrypted)
  • Trust user input without validation

Summary

  • Accessibility: Use accessible, accessibilityLabel, accessibilityRole, accessibilityHint
  • i18next provides multi-language support with translation keys
  • SecureStore encrypts sensitive data at rest
  • Never commit secrets to version control
  • Always validate and sanitize user input
