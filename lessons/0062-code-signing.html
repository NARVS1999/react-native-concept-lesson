Lesson 62: Code Signing for Mobile Apps

Phase 8 — Production Concepts

Lesson Goal Understand how code signing works on both iOS and Android, generate signing keys, and configure your React Native project for production builds.

What is Code Signing?

Code signing is a security mechanism that verifies the identity of the app developer and ensures the app hasn't been tampered with since it was signed. Both Apple and Google require signed apps before they can be installed on devices or distributed through app stores.

iOS Code Signing

iOS code signing involves three key components:

  • Certificates — Digital identities issued by Apple that prove you are the developer
  • Provisioning Profiles — Bundle your certificate, app ID, and allowed devices together
  • Apple Developer Account — Required to create certificates and provisioning profiles ($99/year)

Apple Developer Account Setup

  1. Sign up at developer.apple.com
  2. Join the Apple Developer Program
  3. Create an App ID in the Identifiers section
  4. Generate a Certificate Signing Request (CSR) from Keychain Access
  5. Create a Distribution Certificate
  6. Create a Provisioning Profile linking your certificate to your App ID

Using Fastlane for iOS Signing

# Install Fastlane
gem install fastlane

# Initialize Fastlane in your project
cd ios
fastlane init

# Use match for certificate management
fastlane match development
fastlane match appstore

Android Code Signing

Android uses a keystore file to sign your app. The keystore contains your private key used to sign the APK or AAB (Android App Bundle).

Generating a Keystore with keytool

# Generate a new keystore
keytool -genkeypair \
  -v \
  -storetype PKCS12 \
  -keystore my-release-key.keystore \
  -alias my-key-alias \
  -keyalg RSA \
  -keysize 2048 \
  -validity 10000

# You'll be prompted for:
# - Keystore password
# - Your name and organization
# - City, state, country
# - Key password

Configuring signing in build.gradle

// android/app/build.gradle
android {
    signingConfigs {
        release {
            if (project.hasProperty('MYAPP_RELEASE_STORE_FILE')) {
                storeFile file(MYAPP_RELEASE_STORE_FILE)
                storePassword MYAPP_RELEASE_STORE_PASSWORD
                keyAlias MYAPP_RELEASE_KEY_ALIAS
                keyPassword MYAPP_RELEASE_KEY_PASSWORD
            }
        }
    }

    buildTypes {
        release {
            signingConfig signingConfigs.release
            minifyEnabled true
            proguardFiles getDefaultProguardFile('proguard-android-optimize.txt'), 'proguard-rules.pro'
        }
    }
}

Storing credentials in gradle.properties

# android/gradle.properties
MYAPP_RELEASE_STORE_FILE=my-release-key.keystore
MYAPP_RELEASE_KEY_ALIAS=my-key-alias
MYAPP_RELEASE_STORE_PASSWORD=*****
MYAPP_RELEASE_KEY_PASSWORD=*****
Warning: Never commit gradle.properties with real passwords to version control. Add it to .gitignore or use environment variables.

Expo / EAS Build Signing

EAS Build simplifies the signing process for Expo projects:

# Configure EAS credentials
eas credentials

# For Android, EAS can generate and manage your keystore
eas build:configure

# Build with automatic credentials
eas build --platform android
eas build --platform ios

Best Practices

  • Keep your keystore files and passwords in a secure location — losing them means you can't update your app
  • Use different keystores for development and production
  • For teams, consider using Fastlane match or EAS credentials to share signing info securely
  • Back up your keystore files and certificates immediately after creation
  • Never commit signing credentials to public repositories

Mini-Project: Generate an Android Keystore

Generate a release keystore for your React Native app and configure it in build.gradle:

# Step 1: Generate the keystore
keytool -genkeypair \
  -v \
  -storetype PKCS12 \
  -keystore my-release-key.keystore \
  -alias my-key-alias \
  -keyalg RSA \
  -keysize 2048 \
  -validity 10000

# Step 2: Move it to android/app/
mv my-release-key.keystore android/app/

# Step 3: Create android/key.properties
cat <<EOF > android/key.properties
storePassword=your_store_password
keyPassword=your_key_password
keyAlias=my-key-alias
storeFile=my-release-key.keystore
EOF

# Step 4: Update android/app/build.gradle
# Add signing config using the key.properties file

Verify your signing configuration by running a release build:

cd android && ./gradlew assembleRelease

Summary

  • Code signing verifies developer identity and app integrity for both iOS and Android
  • iOS requires certificates, provisioning profiles, and an Apple Developer account
  • Android uses keystore files generated with keytool
  • Never commit signing credentials to version control — use environment variables or secure storage
  • Back up all keystore files and certificates immediately after creation
  • EAS Build and Fastlane can automate credential management for your projects
