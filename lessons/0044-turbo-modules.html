Lesson 44: Turbo Modules

Phase 5 — Architectural Concepts

Lesson GoalUnderstand React Native's new architecture with Turbo Modules — learn about JSI, lazy loading, synchronous calls, TurboModuleRegistry, and codegen specifications.

What are Turbo Modules?

Turbo Modules are the new type of native modules in React Native's new architecture. They replace the old bridge-based modules with a faster, more efficient system using JSI (JavaScript Interface).

Old Architecture vs New Architecture

FeatureOld (Bridge)New (Turbo Modules)
CommunicationAsynchronous JSONSynchronous JSI
LoadingAll modules at startupLazy loading on demand
Type SafetyNoneCodegen specs
PerformanceSlower (serialization)Faster (direct calls)
MemoryAll modules loadedOnly used modules loaded

JSI: JavaScript Interface

JSI is a lightweight, synchronous bridge that allows JavaScript to call native methods directly. Unlike the old bridge, JSI doesn't serialize/deserialize data — it passes references directly.

How JSI Works

  1. JavaScript holds a direct reference to a C++ host object
  2. When JS calls a native method, JSI invokes the C++ function directly
  3. C++ calls the native platform code (Swift/Kotlin)
  4. Result is returned synchronously without serialization
// With JSI, this is now synchronous!
const result = NativeModules.MyModule.doSomethingSync();
// No need for callbacks or Promises for simple operations

Lazy Loading

Turbo Modules are loaded on demand, not all at startup. This significantly reduces app launch time when you have many native modules.

// Old architecture: ALL modules loaded at startup
// Even if you only use 2 out of 20 modules

// New architecture: Modules loaded when first accessed
import { TurboModuleRegistry } from 'react-native';

// This module is only loaded when getMyModule() is called
function getMyModule() {
  return TurboModuleRegistry.getEnforcing('MyModule');
}

// If you never call getMyModule(), it's never loaded

TurboModuleRegistry

TurboModuleRegistry is the API for accessing Turbo Modules. It provides two methods: get and getEnforcing.

import { TurboModuleRegistry, type TurboModule } from 'react-native';

// getEnforcing - throws if module not found
export function getMyModule(): MyModuleSpec {
  return TurboModuleRegistry.getEnforcing<MyModuleSpec>('MyModule');
}

// get - returns null if module not found (safer)
export function getMyModuleSafe(): MyModuleSpec | null {
  return TurboModuleRegistry.get<MyModuleSpec>('MyModule');
}

// Usage
const myModule = getMyModule();
const result = await myModule.doSomething('data');

Codegen Specifications

Codegen generates type-safe native code from JavaScript specifications. This ensures your native modules match the JS interface exactly.

Creating a Spec File

// specs/MyModule.ts
import type { TurboModule } from 'react-native';
import { TurboModuleRegistry } from 'react-native';

export interface Spec extends TurboModule {
  // Synchronous method
  getConstants(): {
    PI: number;
    VERSION: string;
  };

  // Async method
  getData(key: string): Promise<string>;

  // Method with callback
  subscribe(
    event: string,
    callback: (data: string) => void
  ): void;
}

export default TurboModuleRegistry.getEnforcing<Spec>('MyModule');

Codegen Output

When you run codegen, it generates:

  • iOS: Swift/Obj-C++ protocol that your native module must implement
  • Android: Kotlin/Java abstract class that your native module must extend
// Run codegen
npx react-native codegen

// Output for iOS (generated):
@objc public protocol MyModuleSpec {
  func getConstants() -> NSDictionary
  func getData(_ key: String) async throws -> String
}

// Your native module implements this spec
@objc(MyModule)
public class MyModule: NSObject, MyModuleSpec {
  public func getConstants() -> NSDictionary {
    return ["PI": 3.14159, "VERSION": "1.0"]
  }

  public func getData(_ key: String) async throws -> String {
    return "value for \(key)"
  }
}

Building a Turbo Module

// Step 1: Create the spec
// specs/BatteryModule.ts
import type { TurboModule } from 'react-native';
import { TurboModuleRegistry } from 'react-native';

export interface Spec extends TurboModule {
  getBatteryLevel(): Promise<number>;
  isCharging(): Promise<boolean>;
  getConstants(): {
    LOW_BATTERY_THRESHOLD: number;
  };
}

export default TurboModuleRegistry.getEnforcing<Spec>('BatteryModule');
// Step 2: Implement native module
// ios/BatteryModule.swift
import ExpoModulesCore

public class BatteryModule: Module {
  public func definition() -> ModuleDefinition {
    Name("BatteryModule")

    AsyncFunction("getBatteryLevel") { () -> Double in
      UIDevice.current.isBatteryMonitoringEnabled = true
      return Double(UIDevice.current.batteryLevel)
    }

    AsyncFunction("isCharging") { () -> Bool in
      UIDevice.current.isBatteryMonitoringEnabled = true
      return UIDevice.current.batteryState == .charging
    }

    Constants {
      return [
        "LOW_BATTERY_THRESHOLD": 0.2
      ]
    }
  }
}
// Step 3: Use in JavaScript
// screens/BatteryScreen.js
import { View, Text, StyleSheet } from 'react-native';
import BatteryModule from '../specs/BatteryModule';

export default function BatteryScreen() {
  const [battery, setBattery] = useState(null);

  useEffect(() => {
    async function load() {
      const level = await BatteryModule.getBatteryLevel();
      setBattery(level);
    }
    load();
  }, []);

  const threshold = BatteryModule.getConstants().LOW_BATTERY_THRESHOLD;

  return (
    <View style={styles.container}>
      <Text style={styles.level}>
        Battery: {battery !== null ? `${Math.round(battery * 100)}%` : 'Loading...'}
      </Text>
      {battery !== null && battery < threshold && (
        <Text style={styles.warning}>Low Battery Warning!</Text>
      )}
    </View>
  );
}

Migration Checklist

  • Enable the new architecture in gradle.properties and Podfile
  • Create TypeScript spec files for all native modules
  • Run codegen to generate type-safe interfaces
  • Update native module implementations to match specs
  • Test thoroughly — behavior may differ slightly
  • Use TurboModuleRegistry instead of NativeModules

Summary

  • Turbo Modules replace the old bridge with JSI for faster, synchronous communication
  • JSI enables direct JavaScript-to-native calls without JSON serialization
  • Lazy loading reduces startup time by loading modules only when needed
  • TurboModuleRegistry provides get and getEnforcing to access modules
  • Codegen generates type-safe interfaces from TypeScript spec files
  • The new architecture improves performance, memory usage, and developer experience
