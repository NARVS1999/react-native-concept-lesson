Lesson 66: CI/CD for React Native

Phase 8 — Production Concepts

Lesson Goal Learn how to automate building, testing, and deploying your React Native app using CI/CD pipelines with GitHub Actions, EAS Build, and Fastlane.

What is CI/CD?

Continuous Integration (CI) automatically runs tests and builds when code is pushed to your repository. Continuous Deployment (CD) automatically deploys verified builds to app stores or testing platforms.

  • CI Benefits: Catch bugs early, ensure code quality, automated testing on every push
  • CD Benefits: Faster releases, reduced manual errors, consistent deployment process

GitHub Actions for React Native

GitHub Actions is a free CI/CD platform that runs workflows directly from your GitHub repository.

Basic workflow structure

# .github/workflows/build.yml
name: Build and Test

on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'

      - name: Install dependencies
        run: npm ci

      - name: Run linter
        run: npm run lint

      - name: Run tests
        run: npm test

  build-android:
    needs: test
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'

      - name: Install dependencies
        run: npm ci

      - name: Build Android APK
        run: npx eas-cli build --platform android --profile preview --non-interactive
        env:
          EXPO_TOKEN: ${{ secrets.EXPO_TOKEN }}

EAS Build in CI

EAS Build integrates seamlessly with CI/CD pipelines through the CLI:

# Trigger EAS builds from CI
npx eas-cli build --platform ios --profile production --non-interactive
npx eas-cli build --platform android --profile production --non-interactive

# Trigger EAS updates from CI
npx eas-cli update --branch production --message "CI: automated update"

# Submit builds from CI
npx eas-cli submit --platform all --profile production --non-interactive

Setting up secrets in GitHub

# Add these secrets in your GitHub repo settings:
# Settings → Secrets and variables → Actions

# Required secrets:

# SENTRY_AUTH_TOKEN - For source map uploads
# ANDROID_KEYSTORE_BASE64 - Your keystore file (base64 encoded)
# ANDROID_KEY_PASSWORD - Keystore password
# ANDROID_KEY_ALIAS - Key alias

# Generate base64 keystore for CI
base64 -i my-release-key.keystore | tr -d '\n' > keystore-base64.txt

Fastlane

Fastlane automates building, testing, and releasing iOS and Android apps:

# Install Fastlane
gem install fastlane

# Initialize Fastlane in your project
cd ios && fastlane init
cd android && fastlane init

Fastlane configuration

# ios/Fastfile
default_platform(:ios)

platform :ios do
  desc "Push to TestFlight"
  lane :beta do
    build_app(scheme: "MyApp")
    upload_to_testflight
  end

  desc "Push to App Store"
  lane :release do
    build_app(scheme: "MyApp")
    upload_to_app_store(force: true)
  end
end

# android/Fastfile
default_platform(:android)

platform :android do
  desc "Build and upload to Play Store"
  lane :beta do
    gradle(task: "clean assembleRelease")
    upload_to_play_store(track: "internal")
  end

  lane :release do
    gradle(task: "clean bundleRelease")
    upload_to_play_store
  end
end

Automated Testing in CI

# .github/workflows/test.yml
name: Test Suite

on: [push, pull_request]

jobs:
  unit-tests:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
      - run: npm ci
      - run: npm run test:unit -- --coverage
      - name: Upload coverage
        uses: actions/upload-artifact@v4
        with:
          name: coverage-report
          path: coverage/

  e2e-tests:
    runs-on: macos-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
      - run: npm ci
      - run: npm run build:ios
      - run: npm run test:e2e -- --configuration ios.sim.debug

Build Triggers

  • Push to main — Build and deploy to production
  • Push to develop — Build and deploy to staging/internal testing
  • Pull request — Run tests and build preview version
  • Tag push (v1.0.0) — Trigger release build and store submission
  • Schedule — Nightly builds for testing
# Tag-based release trigger
on:
  push:
    tags:
      - 'v*'

jobs:
  release:
    runs-on: macos-latest
    steps:
      - uses: actions/checkout@v4
      - name: Build iOS
        run: npx eas-cli build --platform ios --profile production --non-interactive
      - name: Build Android
        run: npx eas-cli build --platform android --profile production --non-interactive

Deployment Automation

# Complete CI/CD pipeline
name: Release Pipeline

on:
  push:
    tags:
      - 'v*'

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: npm ci && npm test

  build:
    needs: test
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: npm ci
      - name: Build both platforms
        run: |
          npx eas-cli build --platform ios --profile production --non-interactive
          npx eas-cli build --platform android --profile production --non-interactive

  submit:
    needs: build
    runs-on: ubuntu-latest
    steps:
      - name: Submit to stores
        run: |
          npx eas-cli submit --platform ios --non-interactive
          npx eas-cli submit --platform android --non-interactive

Mini-Project: Create a GitHub Actions Workflow for Builds

Set up a complete CI/CD pipeline for your React Native project:

# Step 1: Create the workflow directory
mkdir -p .github/workflows

# Step 2: Create the workflow file
cat <<EOF > .github/workflows/build.yml
name: React Native CI/CD

on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'
      - run: npm ci
      - run: npm run lint
      - run: npm test

  build-android:
    needs: test
    runs-on: ubuntu-latest
    if: github.ref == 'refs/heads/main'
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'
      - run: npm ci
      - name: Build Android
        run: npx eas-cli build --platform android --profile production --non-interactive
        env:
          EXPO_TOKEN: \${{ secrets.EXPO_TOKEN }}
EOF

# Step 3: Add your Expo token as a GitHub secret
# Go to repo Settings → Secrets → Actions → New repository secret
# Name: EXPO_TOKEN
# Value: your-expo-access-token

# Step 4: Push the workflow to trigger your first build
git add .github/workflows/build.yml
git commit -m "ci: add GitHub Actions build workflow"
git push

Verify the workflow runs successfully in the Actions tab of your GitHub repository.

Summary

  • CI/CD automates testing, building, and deploying your React Native app
  • GitHub Actions provides free CI/CD workflows triggered by code changes
  • EAS Build integrates with CI through the --non-interactive flag and EXPO_TOKEN
  • Fastlane automates native build and store submission processes
  • Store sensitive credentials (tokens, keystores) as encrypted secrets
  • Set up different pipelines for development, staging, and production environments
