Lesson 68: Build Configuration and Environment Management

Phase 8 — Production Concepts

Lesson Goal Learn how to manage environment variables, create different build configurations for development, staging, and production, and use Expo constants to access environment-specific values.

Why Environment Management Matters

Your React Native app needs different configurations depending on where it runs: development, staging, and production. Using the wrong API endpoint or debug flags in production can cause serious issues.

Common environment differences

  • API URLs — localhost for dev, staging server for staging, production URL for prod
  • API Keys — Test keys for development, live keys for production
  • Feature Flags — Experimental features enabled in dev, disabled in prod
  • Logging — Verbose logging in dev, minimal in production
  • Analytics — Test analytics in dev, real tracking in production

Environment Variables with .env Files

Use the react-native-dotenv or react-native-config package to load environment variables from .env files.

Setup with react-native-dotenv

# Install the package
npm install react-native-dotenv

# Create .env files
touch .env .env.development .env.staging .env.production
# .env.development
API_URL=http://localhost:3000
API_KEY=dev-test-key-123
ENABLE_DEBUG=true
LOG_LEVEL=debug
SENTRY_DSN=

# .env.staging
API_URL=https://staging-api.myapp.com
API_KEY=staging-key-456
ENABLE_DEBUG=true
LOG_LEVEL=info
SENTRY_DSN=https://staging@sentry.io/123

# .env.production
API_URL=https://api.myapp.com
API_KEY=prod-key-789
ENABLE_DEBUG=false
LOG_LEVEL=error
SENTRY_DSN=https://prod@sentry.io/456

Configuring babel to use env files

// babel.config.js
module.exports = {
  presets: ['module:@react-native/babel-preset'],
  plugins: [
    ['module:react-native-dotenv', {
      moduleName: '@env',
      path: '.env',
    }],
  ],
};

Using environment variables in code

// Import environment variables
import { API_URL, API_KEY, ENABLE_DEBUG } from '@env';

// Use in your app
const apiClient = {
  baseURL: API_URL,
  headers: {
    'Authorization': `Bearer ${API_KEY}`,
  },
};

// Conditional features based on environment
if (ENABLE_DEBUG === 'true') {
  console.log('Debug mode enabled');
  // Enable debug tools, verbose logging, etc.
}

export { apiClient };

app.config.js for Dynamic Configuration

Expo supports app.config.js (or app.config.ts) for dynamic configuration based on environment:

// app.config.js
export default ({ config }) => {
  const ENV = process.env.APP_ENV || 'development';

  const envConfig = {
    development: {
      name: 'MyApp Dev',
      extra: {
        apiUrl: 'http://localhost:3000',
        sentryDsn: '',
      },
      android: {
        package: 'com.myapp.dev',
      },
      ios: {
        bundleIdentifier: 'com.myapp.dev',
      },
    },
    staging: {
      name: 'MyApp Staging',
      extra: {
        apiUrl: 'https://staging-api.myapp.com',
        sentryDsn: 'https://staging@sentry.io/123',
      },
      android: {
        package: 'com.myapp.staging',
      },
      ios: {
        bundleIdentifier: 'com.myapp.staging',
      },
    },
    production: {
      name: 'MyApp',
      extra: {
        apiUrl: 'https://api.myapp.com',
        sentryDsn: 'https://prod@sentry.io/456',
      },
      android: {
        package: 'com.myapp',
      },
      ios: {
        bundleIdentifier: 'com.myapp',
      },
    },
  };

  return {
    ...config,
    ...envConfig[ENV],
    extra: {
      ...envConfig[ENV].extra,
      env: ENV,
    },
  };
};

Expo Constants for Accessing Config

Use expo-constants to access the extra values defined in app.config.js:

# Install Expo Constants
npx expo install expo-constants
import Constants from 'expo-constants';

// Access environment-specific values
const { apiUrl, sentryDsn, env } = Constants.expoConfig.extra;

console.log('Running in:', env);
console.log('API URL:', apiUrl);

// Use in your app
const API_CONFIG = {
  baseURL: apiUrl,
  timeout: env === 'production' ? 30000 : 60000,
  retries: env === 'production' ? 3 : 0,
};

export { API_CONFIG };

Build Profiles for Different Environments

Combine EAS Build profiles with environment variables:

// eas.json
{
  "build": {
    "development": {
      "developmentClient": true,
      "distribution": "internal",
      "env": {
        "APP_ENV": "development"
      }
    },
    "staging": {
      "distribution": "internal",
      "env": {
        "APP_ENV": "staging"
      }
    },
    "production": {
      "autoIncrement": true,
      "env": {
        "APP_ENV": "production"
      }
    }
  }
}
# Build for different environments
APP_ENV=development eas build --profile development --platform ios
APP_ENV=staging eas build --profile staging --platform android
APP_ENV=production eas build --profile production --platform all

Environment Configuration Module

Create a centralized configuration module for your app:

// config/environment.js
import Constants from 'expo-constants';

const ENV = {
  dev: {
    apiUrl: 'http://localhost:3000',
    enableDebug: true,
    sentryDsn: '',
    analyticsId: 'dev-analytics-id',
  },
  staging: {
    apiUrl: 'https://staging-api.myapp.com',
    enableDebug: true,
    sentryDsn: 'https://staging@sentry.io/123',
    analyticsId: 'staging-analytics-id',
  },
  prod: {
    apiUrl: 'https://api.myapp.com',
    enableDebug: false,
    sentryDsn: 'https://prod@sentry.io/456',
    analyticsId: 'prod-analytics-id',
  },
};

const getEnvVars = () => {
  const env = Constants.expoConfig?.extra?.env || 'dev';
  return ENV[env] || ENV.dev;
};

export default getEnvVars;
// Usage in your app
import getEnvVars from '../config/environment';

const { apiUrl, enableDebug, sentryDsn } = getEnvVars();

if (enableDebug) {
  console.log('Debug mode active');
}

// Initialize services with environment config
Sentry.init({ dsn: sentryDsn });

Best Practices

  • Never commit .env files with real secrets to version control — add them to .gitignore
  • Use .env.example to document required variables without actual values
  • Keep a .env.development file with safe default values for local development
  • Use EAS Build env field to inject secrets during cloud builds
  • Create separate app identifiers for dev, staging, and production builds
  • Centralize your configuration in one module to avoid scattered env var usage

Mini-Project: Create Dev and Production Build Configs

Set up environment management for your React Native project:

# Step 1: Install dependencies
npx expo install expo-constants
npm install react-native-dotenv

# Step 2: Create environment files
cat <<EOF > .env.development
API_URL=http://localhost:3000
API_KEY=dev-test-key
ENABLE_DEBUG=true
EOF

cat <<EOF > .env.production
API_URL=https://api.myapp.com
API_KEY=prod-live-key
ENABLE_DEBUG=false
EOF

# Step 3: Create config module
mkdir -p src/config
cat <<EOF > src/config/environment.js
import Constants from 'expo-constants';

const ENV = {
  development: {
    apiUrl: 'http://localhost:3000',
    enableDebug: true,
  },
  production: {
    apiUrl: 'https://api.myapp.com',
    enableDebug: false,
  },
};

export default function getEnvVars() {
  const env = Constants.expoConfig?.extra?.env || 'development';
  return ENV[env];
}
EOF

# Step 4: Update app.config.js with env-specific settings
cat <<EOF > app.config.js
export default ({ config }) => {
  const ENV = process.env.APP_ENV || 'development';
  const envSettings = {
    development: {
      name: 'MyApp Dev',
      android: { package: 'com.myapp.dev' },
      ios: { bundleIdentifier: 'com.myapp.dev' },
    },
    production: {
      name: 'MyApp',
      android: { package: 'com.myapp' },
      ios: { bundleIdentifier: 'com.myapp' },
    },
  };
  return { ...config, ...envSettings[ENV], extra: { env: ENV } };
};
EOF

# Step 5: Use in your app
# import getEnvVars from './src/config/environment';
# const { apiUrl, enableDebug } = getEnvVars();

Build for both environments and verify each uses the correct configuration.

Summary

  • Environment variables manage different configurations for dev, staging, and production
  • .env files store environment-specific values like API URLs and keys
  • app.config.js provides dynamic configuration based on the build environment
  • expo-constants accesses runtime configuration from Constants.expoConfig.extra
  • Create separate bundle identifiers to install multiple environments on one device
  • Centralize configuration in one module to keep env var usage consistent across your app
