Lesson 0035: Error Boundaries

Phase 4 — Integration Concepts

Lesson Goal Implement class component error boundaries using getDerivedStateFromError and componentDidCatch, provide fallback UI for crashed components, and understand when and where to use Error Boundaries in a React Native app.

What Are Error Boundaries?

Error Boundaries are React components that catch JavaScript errors anywhere in their child component tree, log those errors, and display a fallback UI instead of crashing the entire app. They work like a try-catch block for React components.

Without Error Boundaries, an error in a single component can unmount the entire component tree, showing a blank screen or crashing the app.

Creating an Error Boundary

Error Boundaries must be class components with two special lifecycle methods:

import React, { Component } from 'react';
import { View, Text, StyleSheet } from 'react-native';

class ErrorBoundary extends Component {
  constructor(props) {
    super(props);
    this.state = { hasError: false, error: null };
  }

  static getDerivedStateFromError(error) {
    // Update state so the next render shows fallback UI
    return { hasError: true, error };
  }

  componentDidCatch(error, errorInfo) {
    // Log error to monitoring service
    console.error('ErrorBoundary caught:', error);
    console.error('Component stack:', errorInfo.componentStack);
  }

  render() {
    if (this.state.hasError) {
      return (
        <View style={styles.fallback}>
          <Text style={styles.fallbackTitle}>Something went wrong</Text>
          <Text style={styles.fallbackMessage}>
            {this.state.error?.message || 'An unexpected error occurred.'}
          </Text>
          <Button
            title="Try Again"
            onPress={() => this.setState({ hasError: false, error: null })}
          />
        </View>
      );
    }

    return this.props.children;
  }
}

const styles = StyleSheet.create({
  fallback: {
    flex: 1, justifyContent: 'center', alignItems: 'center',
    padding: 20, backgroundColor: '#fff3f3',
  },
  fallbackTitle: { fontSize: 20, fontWeight: 'bold', color: '#d32f2f', marginBottom: 8 },
  fallbackMessage: { fontSize: 14, color: '#666', textAlign: 'center', marginBottom: 16 },
});

getDerivedStateFromError

This static method is called during the render phase when a child component throws an error. It receives the error and must return an object to update state:

// Called during render — update state to show fallback
static getDerivedStateFromError(error) {
  return { hasError: true, error };
}

Important: This method runs during rendering, so you cannot perform side effects here. Use componentDidCatch for logging.

componentDidCatch

This method is called during the commit phase after an error has been thrown. It receives the error and an error info object with the component stack trace:

// Called after commit — log for debugging
componentDidCatch(error, errorInfo) {
  // Send to error reporting service
  logErrorToService(error, errorInfo.componentStack);
}

Fallback UI Patterns

Design fallback UIs that help users recover gracefully:

// Pattern 1: Simple error message
function FallbackUI({ error, onRetry }) {
  return (
    <View style={styles.fallback}>
      <Text>Oops! Something went wrong.</Text>
      <Button title="Retry" onPress={onRetry} />
    </View>
  );
}

// Pattern 2: Detailed error info for development
function DevFallback({ error, componentStack }) {
  return (
    <View style={styles.devFallback}>
      <Text style={styles.errorTitle}>Error Details</Text>
      <ScrollView>
        <Text style={styles.errorMessage}>{error.message}</Text>
        <Text style={styles.stackTrace}>{componentStack}</Text>
      </ScrollView>
    </View>
  );
}

When to Use Error Boundaries

  • Wrap feature sections: Isolate crashes in one feature from affecting others
  • Wrap complex components: Charts, maps, or third-party components that might fail
  • Wrap screen-level components: Prevent a single screen crash from killing the entire app
  • Avoid wrapping: Event handlers, async code, server-side rendering, and the root component

Mini-Project: Wrap a Risky Component in an Error Boundary

Create an Error Boundary and wrap a component that might throw an error during rendering. Include a retry button that resets the boundary state.

import React, { Component } from 'react';
import { View, Text, Button, StyleSheet } from 'react-native';

// Error Boundary component
class ErrorBoundary extends Component {
  constructor(props) {
    super(props);
    this.state = { hasError: false, error: null };
  }

  static getDerivedStateFromError(error) {
    return { hasError: true, error };
  }

  componentDidCatch(error, errorInfo) {
    console.error('ErrorBoundary caught:', error.message);
    console.error('Component stack:', errorInfo.componentStack);
  }

  render() {
    if (this.state.hasError) {
      return (
        <View style={styles.fallback}>
          <Text style={styles.fallbackTitle}>Component Crashed</Text>
          <Text style={styles.fallbackMessage}>
            {this.state.error?.message}
          </Text>
          <Button
            title="Try Again"
            onPress={() => this.setState({ hasError: false, error: null })}
          />
        </View>
      );
    }
    return this.props.children;
  }
}

// Risky component that might throw
function RiskyComponent({ shouldCrash }) {
  if (shouldCrash) {
    throw new Error('Simulated render error!');
  }
  return (
    <View style={styles.safeContent}>
      <Text style={styles.safeText}>Component is working fine!</Text>
    </View>
  );
}

// App using Error Boundary
export default function App() {
  const [crash, setCrash] = React.useState(false);

  return (
    <View style={styles.container}>
      <Text style={styles.title}>Error Boundary Demo</Text>

      <ErrorBoundary>
        <RiskyComponent shouldCrash={crash} />
      </ErrorBoundary>

      <View style={styles.controls}>
        <Button
          title={crash ? 'Fix Component' : 'Crash Component'}
          onPress={() => setCrash(!crash)}
        />
      </View>
    </View>
  );
}

const styles = StyleSheet.create({
  container: { flex: 1, padding: 20, backgroundColor: '#f5f5f5' },
  title: { fontSize: 24, fontWeight: 'bold', textAlign: 'center', marginBottom: 20 },
  fallback: {
    padding: 20, backgroundColor: '#fff3f3', borderRadius: 8,
    borderWidth: 2, borderColor: '#ffcdd2', marginVertical: 10,
  },
  fallbackTitle: { fontSize: 18, fontWeight: 'bold', color: '#d32f2f', marginBottom: 8 },
  fallbackMessage: { fontSize: 14, color: '#666', marginBottom: 16 },
  safeContent: {
    padding: 20, backgroundColor: '#e8f5e9', borderRadius: 8,
    borderWidth: 2, borderColor: '#a5d6a7', marginVertical: 10,
  },
  safeText: { fontSize: 16, color: '#2e7d32', textAlign: 'center' },
  controls: { marginTop: 20 },
});

Toggle the "Crash Component" button to see the Error Boundary catch the error and show the fallback UI. Click "Try Again" to reset the boundary.

Summary

  • Error Boundaries are class components that catch errors in their child component tree
  • getDerivedStateFromError updates state to render fallback UI (runs during render)
  • componentDidCatch logs errors and component stack traces (runs after commit)
  • Place Error Boundaries around features, screens, and complex components
  • Do not use Error Boundaries for event handlers, async code, or the root component
