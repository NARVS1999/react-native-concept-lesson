What Are Micro-Frontends?

Micro-frontends extend the microservices concept to the frontend. Instead of one monolithic app, you decompose your application into smaller, independently deployable pieces. In React Native, this means different team-owned features can be developed, tested, and deployed separately.

Key PrincipleEach micro-frontend should be a self-contained piece of business functionality that can be independently developed and deployed.

Monolith vs Micro-Frontend

// Monolith: Single codebase, all features together
// src/screens/HomeScreen.js
// src/screens/ProfileScreen.js
// src/screens/SettingsScreen.js
// All tightly coupled, deploy together

// Micro-Frontend: Independent feature packages
// packages/home/src/HomeFeature.js
// packages/profile/src/ProfileFeature.js
// packages/settings/src/SettingsFeature.js
// Each owned by different teams, deployed independently

Module Federation in React Native

Module Federation allows you to load code from separate builds at runtime. While traditional Webpack Module Federation is web-only, React Native has alternatives:

// Using a shared package registry approach
// packages/shared-features/src/index.js
export { HomeFeature } from './HomeFeature';
export { ProfileFeature } from './ProfileFeature';
export { SettingsFeature } from './SettingsFeature';

// App shell loads features dynamically
// App.js
import React, { lazy, Suspense } from 'react';
import { View, ActivityIndicator } from 'react-native';

const HomeFeature = lazy(() => import('home/HomeFeature'));
const ProfileFeature = lazy(() => import('profile/ProfileFeature'));

function App() {
  const [currentFeature, setCurrentFeature] = useState('home');

  return (
    <Suspense fallback={<ActivityIndicator />}>
      {currentFeature === 'home' && <HomeFeature />}
      {currentFeature === 'profile' && <ProfileFeature />}
    </Suspense>
  );
}

Feature Flags

Feature flags let you toggle features without deploying new code. This is essential for micro-frontends to control which features are active:

// Feature flag system
// utils/featureFlags.js
const featureFlags = {
  newCheckout: false,
  darkMode: true,
  betaFeatures: false,
};

export function isFeatureEnabled(flagName) {
  return featureFlags[flagName] === true;
}

// Usage in components
import { isFeatureEnabled } from '../utils/featureFlags';

function CheckoutButton() {
  if (isFeatureEnabled('newCheckout')) {
    return <NewCheckoutFlow />;
  }
  return <LegacyCheckoutFlow />;
}

// Dynamic feature loading with flags
function DynamicFeature({ featureName }) {
  const [Feature, setFeature] = useState(null);

  useEffect(() => {
    if (isFeatureEnabled(featureName)) {
      import(`../features/${featureName}`).then(mod => {
        setFeature(() => mod.default);
      });
    }
  }, [featureName]);

  return Feature ? <Feature /> : null;
}

When to Use Micro-Frontends

  • Large teams (10+) working on the same app
  • Different parts need different release cycles
  • Multiple products sharing a shell app
  • Gradual migration from a monolith
  • Need for independent scaling of features

Mini-Project: Implement a Feature Flag System

Create a complete feature flag system with the following features:

// 1. Create feature flag configuration
// config/featureFlags.js
export const FEATURE_FLAGS = {
  NEW_ONBOARDING: {
    enabled: false,
    rolloutPercentage: 0,
    allowedUsers: [],
  },
  DARK_MODE: {
    enabled: true,
    rolloutPercentage: 100,
  },
  BETA_FEATURES: {
    enabled: false,
    rolloutPercentage: 10,
  },
};

// 2. Create flag evaluation logic
// utils/flagEvaluator.js
import AsyncStorage from '@react-native-async-storage/async-storage';

export async function evaluateFlag(flagName, userId) {
  const flag = FEATURE_FLAGS[flagName];
  if (!flag) return false;
  if (!flag.enabled) return false;
  if (flag.allowedUsers?.includes(userId)) return true;
  if (flag.rolloutPercentage === 100) return true;
  if (flag.rolloutPercentage === 0) return false;
  
  // Consistent hashing for user-based rollout
  const hash = hashString(userId + flagName);
  return (hash % 100) < flag.rolloutPercentage;
}

// 3. Create React hook
// hooks/useFeatureFlag.js
import { useState, useEffect } from 'react';
import { evaluateFlag } from '../utils/flagEvaluator';

export function useFeatureFlag(flagName, userId) {
  const [enabled, setEnabled] = useState(false);

  useEffect(() => {
    evaluateFlag(flagName, userId).then(setEnabled);
  }, [flagName, userId]);

  return enabled;
}

// 4. Usage in components
function OnboardingScreen() {
  const isNewOnboarding = useFeatureFlag('NEW_ONBOARDING', userId);
  
  return isNewOnboarding ? (
    <NewOnboardingFlow />
  ) : (
    <LegacyOnboardingFlow />
  );
}

Summary

  • Micro-frontends decompose monolithic apps into independently deployable pieces
  • Feature flags control feature visibility without code deployments
  • Module federation patterns enable dynamic code loading in React Native
  • Use micro-frontends when teams need independent release cycles
  • Package-based approaches with monorepos work well for React Native micro-frontends
  • Feature flags enable gradual rollouts and A/B testing
  • Consider the overhead—micro-frontends add complexity, so use them when benefits outweigh costs
