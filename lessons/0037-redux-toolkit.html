What is Redux Toolkit?

Redux Toolkit (RTK) is the official, opinionated toolset for Redux. It simplifies store setup, reduces boilerplate, and includes best practices by default. It replaces the old pattern of writing reducers, action types, and action creators manually.

Why Redux Toolkit over plain Redux?

  • Less boilerplate — No more switch/case reducers or action type constants
  • Immer integration — Write "mutating" logic that produces immutable updates
  • Built-in DevTools — Time-travel debugging out of the box
  • RTK Query — Data fetching and caching built into the toolkit

Installation

npm install @reduxjs/toolkit react-redux

Setting Up the Store with configureStore

configureStore replaces createStore. It automatically combines reducers, sets up middleware, and enables Redux DevTools.

// store.js
import { configureStore } from '@reduxjs/toolkit';
import counterReducer from './features/counter/counterSlice';

const store = configureStore({
  reducer: {
    counter: counterReducer,
  },
});

export default store;

Root Level Provider

// App.js
import { Provider } from 'react-redux';
import store from './store';
import HomeScreen from './screens/HomeScreen';

export default function App() {
  return (
    <Provider store={store}>
      <HomeScreen />
    </Provider>
  );
}

Creating Slices with createSlice

A "slice" contains the reducer logic and actions for a specific feature. RTK uses Immer under the hood, so you can write mutating code safely.

// features/counter/counterSlice.js
import { createSlice } from '@reduxjs/toolkit';

const counterSlice = createSlice({
  name: 'counter',
  initialState: { value: 0 },
  reducers: {
    increment: (state) => { state.value += 1; },
    decrement: (state) => { state.value -= 1; },
    incrementByAmount: (state, action) => { state.value += action.payload; },
    reset: (state) => { state.value = 0; },
  },
});

export const { increment, decrement, incrementByAmount, reset } = counterSlice.actions;
export default counterSlice.reducer;

How Immer Works

Inside createSlice, you write code like state.value += 1 which looks like mutation, but Immer creates a new immutable state behind the scenes. Never return a new state object manually — just mutate the draft.

Connecting Components: useSelector and useDispatch

useSelector reads values from the store. useDispatch sends actions to update state.

// screens/HomeScreen.js
import { useSelector, useDispatch } from 'react-redux';
import { increment, decrement, incrementByAmount, reset } from '../features/counter/counterSlice';
import { View, Text, Button, StyleSheet } from 'react-native';

export default function HomeScreen() {
  const count = useSelector((state) => state.counter.value);
  const dispatch = useDispatch();

  return (
    <View style={styles.container}>
      <Text style={styles.count}>Count: {count}</Text>
      <Button title="Increment" onPress={() => dispatch(increment())} />
      <Button title="Decrement" onPress={() => dispatch(decrement())} />
      <Button title="Add 5" onPress={() => dispatch(incrementByAmount(5))} />
      <Button title="Reset" onPress={() => dispatch(reset())} />
    </View>
  );
}

const styles = StyleSheet.create({
  container: { flex: 1, justifyContent: 'center', alignItems: 'center', gap: 10 },
  count: { fontSize: 32, fontWeight: 'bold' },
});

RTK Query for API Calls

RTK Query replaces manual fetch calls with a declarative, cached data-fetching layer. Define endpoints once and get automatic loading states, caching, and re-fetching.

// services/api.js
import { createApi, fetchBaseQuery } from '@reduxjs/toolkit/query/react';

export const api = createApi({
  reducerPath: 'api',
  baseQuery: fetchBaseQuery({ baseUrl: 'https://jsonplaceholder.typicode.com' }),
  endpoints: (builder) => ({
    getPosts: builder.query({
      query: () => '/posts',
    }),
    getPostById: builder.query({
      query: (id) => `/posts/${id}`,
    }),
  }),
});

export const { useGetPostsQuery, useGetPostByIdQuery } = api;

Add API to Store

// store.js
import { configureStore } from '@reduxjs/toolkit';
import { api } from './services/api';

const store = configureStore({
  reducer: {
    [api.reducerPath]: api.reducer,
  },
  middleware: (getDefault) => getDefault().concat(api.middleware),
});

export default store;

Using RTK Query Hooks

// screens/PostsScreen.js
import { useGetPostsQuery } from '../services/api';
import { View, Text, FlatList, ActivityIndicator } from 'react-native';

export default function PostsScreen() {
  const { data: posts, isLoading, error } = useGetPostsQuery();

  if (isLoading) return <ActivityIndicator size="large" />;
  if (error) return <Text>Error loading posts</Text>;

  return (
    <FlatList
      data={posts}
      keyExtractor={(item) => item.id.toString()}
      renderItem={({ item }) => (
        <View style={{ padding: 16 }}>
          <Text style={{ fontWeight: 'bold' }}>{item.title}</Text>
          <Text>{item.body}</Text>
        </View>
      )}
    />
  );
}

Putting It All Together

A complete Redux Toolkit setup in React Native involves: creating slices for each feature, connecting the store with Provider, and using selectors and dispatch in components. RTK Query handles all server state.

Steps:

  1. Install dependencies: npm install @reduxjs/toolkit react-redux

  3. Create features/counter/counterSlice.js with all actions
  4. Wrap your App in Provider

// Example: Adding text input for custom amount
const [amount, setAmount] = useState('');

<TextInput
  value={amount}
  onChangeText={setAmount}
  keyboardType="numeric"
  placeholder="Enter amount"
/>
<Button
  title="Add Amount"
  onPress={() => {
    const num = parseInt(amount) || 0;
    dispatch(incrementByAmount(num));
    setAmount('');
  }}
/>

Summary

  • configureStore simplifies store setup with automatic middleware and DevTools
  • createSlice generates actions and reducers from a single object using Immer
  • Provider connects the Redux store to your React Native component tree
  • useSelector reads state; useDispatch sends actions
  • RTK Query handles server state with automatic caching and re-fetching
  • Never mutate state outside of createSlice — use reducers only
