Lesson 70: Bundle Size Optimization

Phase 9 — Optimization Concepts

Lesson Goal Learn to analyze your app's bundle size, apply tree shaking, use selective imports, replace heavy libraries, and implement lazy loading to reduce the final bundle.

Why Bundle Size Matters

Bundle size directly impacts download time, startup performance, and memory usage. Every unused kilobyte in your bundle takes up space on users' devices and slows down loading — especially on slower networks and lower-end devices.

Bundle Analysis Tools

First, measure what you have. Metro bundler provides a visualizer for React Native bundles.

# Install the metro visualization plugin
npm install --save-dev metro-react-native-babel-preset

# Generate a bundle and analyze it
npx react-native bundle --platform ios --dev false --entry-file index.js --bundle-output /tmp/main.jsbundle

# Use a tool like react-native-bundle-visualizer
npx react-native-bundle-visualizer

The visualizer shows a treemap of your bundle — the largest rectangles represent the biggest modules. This helps you identify which libraries consume the most space.

Tree Shaking

Tree shaking is the bundler's ability to eliminate unused code. Metro (used by React Native) supports tree shaking for ES modules. The key rule: use named imports instead of importing entire libraries.

// BAD — imports the entire lodash library (~70KB)
import _ from 'lodash';
const result = _.debounce(fn, 300);

// GOOD — imports only the function you need (~2KB)
import debounce from 'lodash/debounce';
const result = debounce(fn, 300);

// BAD — imports everything from react-native-elements
import { Button, Icon, Input, Card } from 'react-native-elements';

// GOOD — import only what you use
import Button from 'react-native-elements/dist/Button';
import Icon from 'react-native-elements/dist/Icon';

Selective Imports

Many popular libraries support selective imports. Always check the documentation for the recommended import path.

// moment.js is huge (~300KB with locales)
// Use date-fns instead (~5KB per function)
import { format, addDays, differenceInDays } from 'date-fns';

// If you must use moment, import only needed locales
import moment from 'moment';
import 'moment/locale/en-gb'; // only load the locale you need

// For icons, use react-native-vector-icons selectively
import Icon from 'react-native-vector-icons/FontAwesome'; // one icon set
// NOT import Icon from 'react-native-vector-icons'; // all icon sets

Common heavy libraries and their lighter alternatives:

Lazy Loading for Size Reduction

Split your app so heavy screens load only when navigated to. React Navigation supports lazy loading screens by default.

import React, { Suspense, lazy } from 'react';
import { ActivityIndicator } from 'react-native';
import { createNativeStackNavigator } from '@react-navigation/native-stack';

const HomeScreen = lazy(() => import('./screens/HomeScreen'));
const ProfileScreen = lazy(() => import('./screens/ProfileScreen'));
const SettingsScreen = lazy(() => import('./screens/SettingsScreen'));

const Stack = createNativeStackNavigator();

function AppNavigator() {
  return (
    <Suspense fallback={<ActivityIndicator />}>
      <Stack.Navigator>
        <Stack.Screen name="Home" component={HomeScreen} />
        <Stack.Screen name="Profile" component={ProfileScreen} />
        <Stack.Screen name="Settings" component={SettingsScreen} />
      </Stack.Navigator>
    </Suspense>
  );
}

// Each screen is loaded as a separate chunk
// Only HomeScreen is in the initial bundle
// ProfileScreen and SettingsScreen load on demand

Mini-Project: Analyze and Reduce Your Bundle Size

Use the bundle visualizer to identify the largest dependencies, then replace or tree-shake them.

// Step 1: Install the visualizer
// npm install --save-dev react-native-bundle-visualizer

// Step 2: Run the visualizer
// npx react-native-bundle-visualizer --platform ios

// Step 3: Replace heavy libraries identified in the report

// BEFORE: Using moment (heavy)
import moment from 'moment';
const formatted = moment().format('MMMM Do YYYY');

// AFTER: Using date-fns (lightweight, tree-shakeable)
import { format } from 'date-fns';
const formatted = format(new Date(), 'MMMM do yyyy');

// BEFORE: Using lodash (heavy)
import _ from 'lodash';
const filtered = _.filter(items, { active: true });
const sorted = _.sortBy(items, 'name');

// AFTER: Using lodash-es (tree-shakeable)
import filter from 'lodash/filter';
import sortBy from 'lodash/sortBy';
const filtered = filter(items, { active: true });
const sorted = sortBy(items, 'name');

// Step 4: Verify the improvement
// Run the visualizer again and compare the bundle sizes

After making changes, regenerate the bundle and compare the size before and after.

Summary

  • Bundle size impacts download time, startup speed, and memory usage
  • Use react-native-bundle-visualizer to analyze what takes up space in your bundle
  • Tree shaking eliminates unused code — use named imports and avoid default imports of entire libraries
  • Selective imports let you load only specific parts of a library (e.g., lodash/debounce)
  • Replace heavy libraries with lighter alternatives (date-fns over moment, fetch over axios)
  • Lazy loading screens defers non-critical code to reduce initial bundle size
  • Always measure before and after changes to confirm improvements
