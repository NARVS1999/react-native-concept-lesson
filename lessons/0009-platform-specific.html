Lesson 0009: Platform-Specific Code

Phase 3 — Implementation Concepts

Lesson Goal Write platform-specific code for iOS and Android using Platform API and file extensions.

Platform.select

The Platform.select function lets you choose values based on the current platform:

import { Platform, StyleSheet } from 'react-native';

const styles = StyleSheet.create({
  container: {
    ...Platform.select({
      ios: { shadowColor: '#000', shadowOffset: { width: 0, height: 2 } },
      android: { elevation: 4 },
    }),
  },
});

Platform.OS

Check the platform directly with Platform.OS — returns 'ios' or 'android':

import { Platform, Text } from 'react-native';

function PlatformText() {
  return (
    <Text>
      {Platform.OS === 'ios' ? 'Press the back button' : 'Press the back button'}
    </Text>
  );
}

Platform-Specific Files

You can create separate files for each platform using file extensions:

FilePlatform
Button.ios.jsiOS only
Button.android.jsAndroid only
Button.jsFallback for both
// When you import Button, React Native automatically picks the right file:
import Button from './Button'; // Uses Button.ios.js on iOS, Button.android.js on Android
When to use file extensions Use platform-specific files when the entire component or module differs significantly between platforms. For minor differences, use Platform.select or Platform.OS checks.

Platform.Version

Check the OS version for feature-specific logic:

import { Platform } from 'react-native';

if (Platform.OS === 'android' && Platform.Version >= 33) {
  // Android 13+ specific code
}

if (Platform.OS === 'ios') {
  const version = parseInt(Platform.Version, 10);
  if (version >= 16) {
    // iOS 16+ specific code
  }
}

Summary

  • Platform.select({ ios: ..., android: ... }) for platform-specific values
  • Platform.OS returns 'ios' or 'android'
  • Platform-specific file extensions (.ios.js, .android.js) for entirely different implementations
  • Platform.Version checks the OS version
