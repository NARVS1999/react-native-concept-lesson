Lesson 8: Platform API

Phase 1 — Foundational Concepts

Lesson Goal By the end of this lesson, you will understand how to detect the current platform and OS version, how to use platform-specific file extensions, when to use each approach, and how to use Platform.select for inline platform differences.

Platform.OS

The Platform module from React Native provides information about the running platform. The most basic use is Platform.OS, which returns either "ios" or "android".

import { Platform, Text, View, StyleSheet } from 'react-native';

function PlatformExample() {
  return (
    <View style={styles.container}>
      <Text>Running on: {Platform.OS}</Text>

      {Platform.OS === 'ios' ? (
        <Text style={styles.iosText}>This is iOS!</Text>
      ) : (
        <Text style={styles.androidText}>This is Android!</Text>
      )}
    </View>
  );
}

Common use cases for Platform.OS:

  • Showing platform-specific UI elements
  • Calling platform-specific APIs
  • Applying different styles per platform
  • Platform-specific navigation behavior

Platform.Version

On Android, Platform.Version returns a number representing the API level. On iOS, it returns a string representing the OS version.

import { Platform, Text, View } from 'react-native';

function VersionExample() {
  // Android: Platform.Version is a number (e.g., 33 for Android 13)
  // iOS: Platform.Version is a string (e.g., "16.4")

  const getMinVersionMessage = () => {
    if (Platform.OS === 'android') {
      // Android API level check
      if (Platform.Version >= 33) {
        return 'Android 13 or higher';
      } else if (Platform.Version >= 29) {
        return 'Android 10 or higher';
      }
      return 'Older Android version';
    }

    if (Platform.OS === 'ios') {
      // iOS version check (string comparison works for simple cases)
      const majorVersion = parseInt(Platform.Version.split('.')[0], 10);
      if (majorVersion >= 16) {
        return 'iOS 16 or higher';
      } else if (majorVersion >= 14) {
        return 'iOS 14 or higher';
      }
      return 'Older iOS version';
    }

    return 'Unknown platform';
  };

  return (
    <View>
      <Text>Platform: {Platform.OS}</Text>
      <Text>Version: {Platform.Version}</Text>
      <Text>{getMinVersionMessage()}</Text>
    </View>
  );
}

Platform-Specific File Extensions

React Native's Metro bundler supports platform-specific file extensions. When you import a module, Metro automatically resolves the correct file based on the running platform.

The resolution order for import Button from './Button':

  1. Button.ios.js (iOS only)
  2. Button.android.js (Android only)
  3. Button.native.js (Both mobile platforms)
  4. Button.js (Default/fallback)
// Button.ios.js - iOS-specific implementation
import React from 'react';
import { TouchableOpacity, Text, StyleSheet } from 'react-native';

export default function Button({ title, onPress }) {
  return (
    <TouchableOpacity style={styles.iosButton} onPress={onPress}>
      <Text style={styles.iosButtonText}>{title}</Text>
    </TouchableOpacity>
  );
}

const styles = StyleSheet.create({
  iosButton: {
    backgroundColor: '#007AFF',
    borderRadius: 8,
    paddingVertical: 12,
    paddingHorizontal: 24,
  },
  iosButtonText: {
    color: '#fff',
    fontSize: 16,
    fontWeight: '600',
  },
});
// Button.android.js - Android-specific implementation
import React from 'react';
import { TouchableNativeFeedback, Text, StyleSheet } from 'react-native';

export default function Button({ title, onPress }) {
  return (
    <TouchableNativeFeedback
      onPress={onPress}
      background={TouchableNativeFeedback.Ripple('#fff', false)}
    >
      <Text style={styles.androidButtonText}>{title}</Text>
    </TouchableNativeFeedback>
  );
}

const styles = StyleSheet.create({
  androidButtonText: {
    backgroundColor: '#6200EE',
    color: '#fff',
    fontSize: 16,
    fontWeight: '600',
    paddingVertical: 12,
    paddingHorizontal: 24,
    textAlign: 'center',
    borderRadius: 4,
    overflow: 'hidden',
  },
});
// Button.native.js - Shared mobile implementation
import React from 'react';
import { TouchableOpacity, Text, StyleSheet } from 'react-native';

export default function Button({ title, onPress }) {
  return (
    <TouchableOpacity style={styles.button} onPress={onPress}>
      <Text style={styles.buttonText}>{title}</Text>
    </TouchableOpacity>
  );
}

const styles = StyleSheet.create({
  button: {
    backgroundColor: '#3b82f6',
    borderRadius: 8,
    paddingVertical: 12,
    paddingHorizontal: 24,
  },
  buttonText: {
    color: '#fff',
    fontSize: 16,
    fontWeight: '600',
  },
});

When to use each approach:

  • .ios.js / .android.js: When the platforms need completely different implementations
  • .native.js: When you need a mobile-specific implementation but both platforms are the same
  • .js: The default fallback — use this for shared code

When to Use Each Approach

Scenario Best Approach
Small style differences Platform.select or Platform.OS inline
Different component implementations Platform-specific file extensions
Version-dependent features Platform.Version check
Entirely different screens per platform Platform-specific file extensions
Simple conditional styles Platform.select

Platform.select for Inline Differences

Platform.select is a helper that takes an object with ios and android keys and returns the value for the current platform. It's perfect for inline platform differences.

import { Platform, StyleSheet } from 'react-native';

// Simple value selection
const headerHeight = Platform.select({
  ios: 44,
  android: 56,
});

// In StyleSheet.create
const styles = StyleSheet.create({
  container: {
    flex: 1,
    paddingTop: Platform.select({
      ios: 44,    // Status bar + navigation bar height on iOS
      android: 56, // Standard toolbar height on Android
    }),
  },
  shadow: {
    ...Platform.select({
      ios: {
        shadowColor: '#000',
        shadowOffset: { width: 0, height: 2 },
        shadowOpacity: 0.25,
        shadowRadius: 3.84,
      },
      android: {
        elevation: 4,
      },
    }),
  },
  font: {
    ...Platform.select({
      ios: {
        fontFamily: 'System',
      },
      android: {
        fontFamily: 'Roboto',
      },
    }),
  },
});

Practical Examples

Here are real-world patterns you will use frequently:

import { Platform, StyleSheet, StatusBar } from 'react-native';

// Safe area top padding that works on both platforms
const SAFE_TOP = Platform.OS === 'ios' ? 44 : StatusBar.currentHeight || 0;

// Platform-specific header styling
const headerStyles = StyleSheet.create({
  header: {
    backgroundColor: Platform.select({
      ios: '#f8f8f8',
      android: '#6200EE',
    }),
    paddingTop: SAFE_TOP,
    ...Platform.select({
      ios: {
        shadowColor: '#000',
        shadowOffset: { width: 0, height: 1 },
        shadowOpacity: 0.1,
        shadowRadius: 4,
      },
      android: {
        elevation: 4,
      },
    }),
  },
  headerTitle: {
    color: Platform.select({
      ios: '#000',
      android: '#fff',
    }),
    fontSize: 18,
    fontWeight: '600',
  },
});

Create a WelcomeCard component that displays different content and styling per platform:

import WelcomeMessage from './WelcomeMessage';

Summary

  • Platform.OS returns "ios" or "android" for the current platform
  • Platform.Version returns API level (number) on Android and OS version (string) on iOS
  • Platform-specific file extensions (.ios.js, .android.js) let Metro auto-resolve the right file
  • .native.js serves as a fallback for both mobile platforms
  • Platform.select({ ios: ..., android: ... }) picks the right value inline
  • Use file extensions for completely different implementations, and Platform.select for small inline differences
  • Always consider the default .js file as the fallback
