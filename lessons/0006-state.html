Lesson 6: State

Phase 1 — Foundational Concepts

Lesson Goal By the end of this lesson, you will understand what state is, how it differs from props, how state triggers re-renders, the importance of state immutability, state lifting, and how to manage complex state objects.

What Is State?

State is data that belongs to a component and can change over time. While props are external data passed into a component, state is internal data that a component manages itself. When state changes, React Native re-renders the component to reflect the new data on screen.

State is what makes your app interactive. Without state, your app would be a static display. With state, you can track user input, fetch data from APIs, toggle UI elements, and respond to events.

import React, { useState } from 'react';
import { View, Text, Button, StyleSheet } from 'react-native';

function Counter() {
  // useState returns [currentValue, setterFunction]
  const [count, setCount] = useState(0);

  return (
    <View style={styles.container}>
      <Text style={styles.count}>Count: {count}</Text>
      <Button title="Add 1" onPress={() => setCount(count + 1)} />
    </View>
  );
}

The useState hook takes an initial value and returns an array with two elements: the current state value and a function to update it. When you call the setter function, React Native schedules a re-render of the component.

State vs Props

Understanding the difference between state and props is fundamental:

Feature Props State
Source Passed from parent component Managed within the component
Mutability Read-only (immutable) Can be changed via setter
Re-renders Changes trigger re-render Changes trigger re-render
Purpose Configure a component Track interactive data
Scope Component receives from outside Component owns and controls 
// Props come from outside
function Parent() {
  return <Child name="Alice" />;  // "Alice" is a prop
}

// State is internal
function Child({ name }) {
  const [age, setAge] = useState(25);  // age is state

  return (
    <View>
      <Text>{name} is {age} years old</Text>
    </View>
  );
}

How State Triggers Re-Renders

When you call a state setter function, React Native does two things:

  1. It updates the state value to the new value you provided
  2. It schedules a re-render of the component (and its children)

This re-render is how the UI stays in sync with your data. React compares the new JSX with the previous JSX and updates only the parts of the native view tree that changed.

function ToggleExample() {
  const [isVisible, setIsVisible] = useState(false);

  // This will cause a re-render
  const toggle = () => {
    setIsVisible(!isVisible); // State changes, component re-renders
  };

  return (
    <View>
      <Button title="Toggle" onPress={toggle} />
      {isVisible && <Text>Now you see me!</Text>}
    </View>
  );
}

// Important: Batched updates
function BatchExample() {
  const [count, setCount] = useState(0);
  const [name, setName] = useState('');

  const handleClick = () => {
    // These two updates are batched into one re-render
    setCount(count + 1);
    setName('Updated');
  };

  return (/* ... */);
}

State Immutability

You must never modify state directly. Always create a new value when updating state, especially for objects and arrays. Direct mutation prevents React from detecting changes, causing your UI to not update.

// WRONG - direct mutation (will NOT re-render)
function BadTodoList() {
  const [todos, setTodos] = useState(['Buy milk', 'Walk dog']);

  const addTodo = () => {
    todos.push('New todo');     // Direct mutation - BAD!
    setTodos(todos);            // Same reference - no re-render!
  };

  return (/* ... */);
}

// CORRECT - immutable update
function GoodTodoList() {
  const [todos, setTodos] = useState(['Buy milk', 'Walk dog']);

  const addTodo = () => {
    setTodos([...todos, 'New todo']);  // New array - triggers re-render
  };

  const removeTodo = (index) => {
    setTodos(todos.filter((_, i) => i !== index));  // New array
  };

  return (/* ... */);
}

// CORRECT - immutable object update
function ProfileEditor() {
  const [user, setUser] = useState({ name: 'Alice', age: 25 });

  const updateAge = () => {
    setUser({ ...user, age: user.age + 1 });  // New object
  };

  const updateName = (newName) => {
    setUser({ ...user, name: newName });  // New object with spread
  };

  return (/* ... */);
}

// CORRECT - immutable array update with items
function TodoApp() {
  const [todos, setTodos] = useState([
    { id: 1, text: 'Learn React', completed: false },
    { id: 2, text: 'Learn Native', completed: false },
  ]);

  const toggleTodo = (id) => {
    setTodos(todos.map(todo =>
      todo.id === id ? { ...todo, completed: !todo.completed } : todo
    ));
  };

  return (/* ... */);
}

State Lifting

When two sibling components need to share state, lift the state up to their closest common parent. The parent holds the state and passes it down as props.

// LIFTED STATE - parent manages shared state
function TemperatureConverter() {
  const [celsius, setCelsius] = useState('');

  const fahrenheit = celsius ? (parseFloat(celsius) * 9) / 5 + 32 : '';

  return (
    <View>
      {/* Parent passes state down as props */}
      <TemperatureInput
        scale="celsius"
        temperature={celsius}
        onTemperatureChange={setCelsius}
      />
      <TemperatureInput
        scale="fahrenheit"
        temperature={fahrenheit.toString()}
        onTemperatureChange={(f) => {
          setCelsius(((parseFloat(f) - 32) * 5) / 9);
        }}
      />
      <BoilingVerdict celsius={parseFloat(celsius) || 0} />
    </View>
  );
}

// Child components receive state as props
function TemperatureInput({ scale, temperature, onTemperatureChange }) {
  return (
    <View>
      <Text>Enter temperature in {scale}:</Text>
      <TextInput
        value={temperature}
        onChangeText={onTemperatureChange}
        keyboardType="numeric"
      />
    </View>
  );
}

Complex State Objects

For components with multiple related state values, using a single state object can be cleaner.

// Using a state object for related values
function UserForm() {
  const [formData, setFormData] = useState({
    firstName: '',
    lastName: '',
    email: '',
    age: 0,
  });

  // Helper to update a single field
  const updateField = (field, value) => {
    setFormData(prev => ({ ...prev, [field]: value }));
  };

  return (
    <View style={styles.form}>
      <TextInput
        placeholder="First Name"
        value={formData.firstName}
        onChangeText={(val) => updateField('firstName', val)}
      />
      <TextInput
        placeholder="Last Name"
        value={formData.lastName}
        onChangeText={(val) => updateField('lastName', val)}
      />
      <TextInput
        placeholder="Email"
        value={formData.email}
        onChangeText={(val) => updateField('email', val)}
        keyboardType="email-address"
      />
      <Button
        title="Submit"
        onPress={() => console.log(formData)}
      />
    </View>
  );
}

// Functional state updates (when new state depends on previous)
function Counter() {
  const [count, setCount] = useState(0);

  // Use function form when new state depends on previous
  const increment = () => setCount(prev => prev + 1);
  const decrement = () => setCount(prev => prev - 1);
  const reset = () => setCount(0);

  return (
    <View>
      <Text>{count}</Text>
      <Button title="+" onPress={increment} />
      <Button title="-" onPress={decrement} />
      <Button title="Reset" onPress={reset} />
    </View>
  );
}

Mini-Project: Build a Counter with Increment, Decrement, and Reset

Create a fully functional counter app with state management:

import React, { useState } from 'react';
import { View, Text, TouchableOpacity, StyleSheet } from 'react-native';

export default function Counter() {
  const [count, setCount] = useState(0);

  const increment = () => setCount(prev => prev + 1);
  const decrement = () => setCount(prev => prev - 1);
  const reset = () => setCount(0);

  const getCountColor = () => {
    if (count > 0) return '#22c55e';
    if (count < 0) return '#ef4444';
    return '#374151';
  };

  return (
    <View style={styles.container}>
      <Text style={styles.title}>Counter App</Text>

      <View style={styles.countContainer}>
        <Text style={[styles.count, { color: getCountColor() }]}>
          {count}
        </Text>
      </View>

      <View style={styles.buttonRow}>
        <TouchableOpacity
          style={[styles.button, styles.decrementButton]}
          onPress={decrement}
        >
          <Text style={styles.buttonText}>-</Text>
        </TouchableOpacity>

        <TouchableOpacity
          style={[styles.button, styles.resetButton]}
          onPress={reset}
        >
          <Text style={styles.buttonText}>Reset</Text>
        </TouchableOpacity>

        <TouchableOpacity
          style={[styles.button, styles.incrementButton]}
          onPress={increment}
        >
          <Text style={styles.buttonText}>+</Text>
        </TouchableOpacity>
      </View>

      <Text style={styles.hint}>
        {count === 0
          ? 'Start counting!'
          : count > 0
          ? 'Going up!'
          : 'Going down!'}
      </Text>
    </View>
  );
}

Summary

  • State is internal, mutable data managed by a component using useState
  • Props are external, read-only data passed from parent to child
  • Calling a state setter triggers a re-render of the component
  • Always update state immutably — never modify arrays or objects directly
  • Use the spread operator (...) to create new copies of state
  • Lift state up to the closest common parent when siblings need to share data
  • Use functional updates (setState(prev => ...)) when new state depends on previous state
  • Group related values in a state object for cleaner code
