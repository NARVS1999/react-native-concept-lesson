Lesson 64: Over-the-Air (OTA) Updates

Phase 8 — Production Concepts

Lesson Goal Learn how to push JavaScript-only updates to your React Native app without going through the app store review process using EAS Update.

What are OTA Updates?

Over-the-Air (OTA) updates allow you to push updates to your React Native app's JavaScript bundle directly to users' devices without requiring them to download a new version from the app store. This is possible because React Native separates the JavaScript code from the native shell.

Key Limitation: OTA updates can only modify JavaScript code, images, and other JS-bundled assets. They cannot change native code, native modules, or update dependencies that require native compilation.

OTA Updates vs Full Releases

FeatureOTA UpdateFull App Store Release
What can changeJS code, assets, imagesEverything (native + JS)
Review processNone — instant delivery1-7 days for store review
User action requiredNone — automaticMust download update
Rollback possibleYes — immediatelyNo — must submit new version
Use caseBug fixes, content updates, UI tweaksNew features, native changes

Setting Up EAS Update

# Install EAS Update in your project
npx eas-cli update --configure

# Or add manually to app.json
{
  "expo": {
    "updates": {
      "url": "https://u.expo.dev/YOUR_PROJECT_ID",
      "fallbackToCacheTimeout": 0,
      "checkAutomatically": "ON_LOAD"
    }
  }
}

Configure update behavior

// app.json or app.config.js
{
  "expo": {
    "updates": {
      "url": "https://u.expo.dev/YOUR_PROJECT_ID",
      "fallbackToCacheTimeout": 0,
      "checkAutomatically": "ON_LOAD",
      "resourceHeaders": {
        "expo-channel-name": "production"
      }
    }
  }
}

Using EAS Update

# Install EAS Update
npm install -g eas-cli

# Create an update on the main branch
eas update --branch production --message "Fix login bug"

# Create an update on a preview branch
eas update --branch preview --message "Test new feature"

# Check for updates programmatically in your app
npx expo install expo-updates

Checking for updates in code

import * as Updates from 'expo-updates';
import { useEffect } from 'react';

export default function App() {
  useEffect(() => {
    async function checkForUpdates() {
      try {
        const update = await Updates.checkForUpdateAsync();
        if (update.isAvailable) {
          await Updates.fetchUpdateAsync();
          // Reload the app to apply the update
          await Updates.reloadAsync();
        }
      } catch (error) {
        console.log('Error checking for updates:', error);
      }
    }

    checkForUpdates();
  }, []);

  return (
    // Your app component
  );
}

Branch Strategy for OTA Updates

EAS Update uses branches to organize updates. Align your update branches with your release channels:

# Development updates (for dev builds)
eas update --branch development --message "Dev: test new API"

# Staging updates (for preview builds)
eas update --branch staging --message "Staging: content update"

# Production updates (for production builds)
eas update --branch production --message "Fix: resolve crash on startup"

Mapping branches to build profiles

{
  "build": {
    "development": {
      "developmentClient": true,
      "distribution": "internal"
    },
    "preview": {
      "distribution": "internal"
    },
    "production": {
      "autoIncrement": true
    }
  },
  "update": {
    "development": { "channel": "development" },
    "preview": { "channel": "staging" },
    "production": { "channel": "production" }
  }
}

Rollback Capability

One of the most powerful features of OTA updates is the ability to instantly roll back a problematic update:

# Rollback the latest update on a branch
eas update:rollback --branch production

# Or roll back to a specific update
eas update --branch production --message "Rollback: revert to previous version"

This is invaluable when a JavaScript update introduces a critical bug — you can roll back immediately without waiting for app store approval.

Best Practices

  • Test OTA updates in preview/staging environments before pushing to production
  • Use descriptive update messages for easy tracking and rollback decisions
  • Monitor update adoption rates using EAS Update analytics
  • Don't rely on OTA for critical security patches — use full releases for those
  • Keep your OTA updates small and focused on specific changes
  • Consider implementing a version check in your app to ensure compatibility

Summary

  • OTA updates deliver JavaScript-only changes directly to devices without app store review
  • They cannot modify native code, native modules, or dependencies requiring native compilation
  • EAS Update uses branches to organize and target updates to specific build channels
  • Rollbacks are instant and can be triggered with eas update:rollback
  • OTA updates are ideal for bug fixes, content updates, and UI tweaks
  • Always test updates in staging environments before pushing to production
